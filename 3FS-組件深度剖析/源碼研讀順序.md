## Phase 4 — 讀路徑走一遍（1–2 天）★ 最高投報率

比寫路徑單純（無 CRAQ 轉發），但一次穿過整個系統。

```
src/fuse/FuseOps.cc                       read handler
  ↓
src/fuse/PioV.cc                          切成 chunk 級請求
  ↓
src/client/storage/StorageClient.h        先讀介面
src/client/storage/TargetSelection.h      六種副本選取策略
  ↓
src/client/storage/StorageClientImpl.cc   2560 行，客戶端 IO 心臟
  ↓
src/storage/service/StorageOperator.cc    batchRead
  ↓
src/storage/aio/AioStatus.cc              io_uring / libaio 兩實作
  ↓
src/storage/store/ChunkFileView.cc:53-63  O_DIRECT 對齊判定
```

**盯住**：buffer 誰配置、誰註冊給 RDMA、資料被複製幾次。

## Phase 5 — 寫路徑與 CRAQ（2 天）

- [ ] `src/storage/service/StorageOperator.cc` write/update — 入口
- [ ] `src/storage/service/ReliableForwarding.cc` — 逐跳轉發，每跳單邊 RDMA **Read** 從前驅拉資料
- [ ] `src/storage/store/ChunkReplica.cc` — `commitVer`/`updateVer`/`chainVer` 不變式
- [ ] `src/storage/sync/ResyncWorker.cc` — 前驅主動 PUSH 給後繼

## Phase 6 — 元資料（1–2 天）

- [ ] `src/meta/store/ops/Open.cc` — 從最常用的操作入手
- [ ] `src/meta/store/PathResolve.cc` — 路徑解析與逐層權限檢查
- [ ] `src/meta/store/ops/Rename.cc` — 跨多 key 原子操作，最難的一個
- [ ] `src/meta/components/GcManager.cc` — 所有刪除的統一入口
- [ ] `src/meta/components/InodeIdAllocator.h` — 32 分片 FDB 計數器 + 4096 批次行程內佇列

## Phase 7 — mgmtd（1 天）

- [ ] `src/mgmtd/store/MgmtdStore.cc:154-189` `extendLease` — 全部選主邏輯就這一個函式
